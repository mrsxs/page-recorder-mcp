# Page Recorder · 操作与接口录制

Chrome 扩展（Manifest V3）：录制页面操作，抓取接口的请求参数和返回数据，导出成能在浏览器中直接执行的脚本。录制下来的每个接口都会拆成一个独立的工具函数；配合本地桥接服务，Claude Code、Accio 等 AI 工具可以直接在你的浏览器里执行脚本并拿到结果。

## 安装

需要 Node 18+，不用装任何依赖。

```bash
npx -y page-recorder-mcp@latest extension     # 生成浏览器扩展，默认放到 ~/page-recorder-extension（可以跟一个目录参数）
```

1. 打开 `chrome://extensions`，开启右上角「开发者模式」
2. 点「加载已解压的扩展程序」，选择上面生成的文件夹（从源码用的话，选本仓库根目录）
3. 安装前已打开的页面请刷新一次，否则抓不到首屏请求

**以后升级不用手动操作**：AI 工具启动桥接时，发现有新版就更新这个文件夹并重新加载扩展（正在录制、回放时等忙完再更新），已安装的 WorkBuddy、Claude Code 技能也一起更新。自己「加载已解压的扩展程序」选的文件夹（比如下载解压的）也一样会更新：桥接按扩展 ID 从 Chrome、Edge、Chromium、Brave 的资料里找到它，源码目录（带 `.git`）不动。请一直用这个文件夹（换文件夹会变成另一个扩展），并保持「开发者模式」打开：一关掉 Chrome 就会停用已解压的扩展，重新打开后在扩展卡片上启用即可。不想自动更新：在扩展「设置」里关掉，这个开关任何情况下都生效。启动桥接时加 `--no-auto-update`（`PR_AUTO_UPDATE=0`）只影响这个进程和它拉起的后台桥接，别的 AI 工具已经起好的后台桥接不受影响。

从 1.5.0 或更早版本升上来时手动做最后一次，目录写你现在加载的那个：`npx -y page-recorder-mcp@latest extension <现有扩展目录>`，然后在扩展卡片上点「重新加载」，**重启 AI 工具**（旧的后台桥接退出后，备份和自动更新才生效），并**刷新已打开的页面**（否则这些页面录不到接口的返回内容）。

**脚本不会因为升级丢失**：连上桥接后，脚本库自动同步到 `~/.page-recorder/library/`，每个浏览器资料一个目录，互不影响。备份和录制包一样脱敏：不含 AI Key 和密码框的内容（关了密码脱敏录的脚本恢复后要重新填密码），地址里的令牌、签名和响应里的敏感字段也不保留，起始地址带这类参数的脚本恢复后可能要重新录制。这个目录不在扩展文件夹和 npm 缓存里。卸载或换目录重装扩展后，打开「脚本库」页点「恢复到这个浏览器」就能找回；换了目录的按导入的录制包对待，部分需要页面签名的接口要用页面回放。录完还没连过桥接的脚本只在扩展里，卸载前先启动一次桥接。

## 录制

1. 打开目标页面，点扩展图标 →「开始录制」。可以先给录制起个名字，不填也可以，AI 解读后会建议一个
2. 正常操作页面。点击、双击、右键、输入、下拉选择、勾选、回车 / Tab / 方向键 / 快捷键、页面和表格等容器的滚动、拖动、上传、页面跳转、原生确认框的选择都会被记录，页面发出的请求和返回数据会被抓取（见下面“抓哪些请求”）。Shadow DOM（open）里的元素也能录
3. **Alt+点击**：标记要提取数据的元素（回放后在结果的 `extracted` 中返回）；**Alt+Shift+点击**：提取它所在的整个表格或列表
4. 点页面右下角或弹窗里的「停止」，录制会自动存入**脚本库**

密码输入默认不保存明文，会变成脚本参数，回放前再填：明文只交给扩展后台的内存（不落盘，停止录制就清掉），之后请求里出现同一个值就换成占位符、关联到密码参数；点过“显示密码”的框也照样按密码处理。请求入库前，名字像密码、令牌、签名、CSRF 的查询参数和请求体字段（`loginPwd`、`j_password`、`access_token`、`_csrf`……）就会被脱敏；Authorization、Token、Cookie 这类请求头和非标准请求头里像令牌的长串，在导出、给 AI 的内容里都会被隐藏。

**抓哪些请求**：

| 请求 | 怎么抓到的 | 返回内容 |
|---|---|---|
| fetch / XHR（包括页面一打开最早的那几条、iframe 里的） | 页面里的钩子 | 有 |
| JSONP（`<script src="…?callback=fn">`，淘宝、1688 的 mtop 和老系统的跨域接口常用） | 包住回调函数 | 有 |
| 页面新建的空白 iframe（`about:blank`、`srcdoc`）里发的 fetch / XHR | 钩子接进去 | 有 |
| EventSource 推送、WebSocket | 记下连接和开头的 20 条消息 | 开头几条（不能直接请求） |
| sendBeacon | 页面里的钩子 | 没有（浏览器不给） |
| Worker 里发的请求、表单提交（整页提交和提交到 iframe）、点链接下载 / 导出的文件、钩子装上之前就把 fetch 拿走的代码 | 浏览器层面补记（`webRequest`，只在录制期间看录制的标签页） | 没有，只有地址、方法、请求头、请求体、状态和返回头 |
| 录制中的标签页打开的新标签页（详情页、导出页）里的请求 | 同上面各种方式 | 同上 |

图片、字体、样式、脚本文件这些静态资源和统计埋点默认不保留（设置里可以改）；返回类型是 `octet-stream`、`javascript` 的请求只有地址本身像静态文件才丢，导出的文件和 JSONP 会留下。回放时“等接口返回”只等页面自己用 fetch / XHR 发的那些。

**日期框、下拉组件、联想输入这类“在面板里点选出值”的控件**，录成「设置日期 … 为 {{参数}}」「选择 … 为 {{参数}}」这样的一步，值就是输入参数，可以改。原理不依赖具体组件库：点开某个输入框后，它的值被页面脚本改了（没有键盘输入），就记成“设置这个框的值”，期间在控件和它弹出的面板里的点击作为这一步的成员保留（时间线上不单独显示，删掉这一步会恢复成原来的点击）。回放时：

- 日期：jQuery UI 用它自己的 setDate；能输入的日期框真实键入后按 Tab 确认；其余打开日历面板，按面板上的年月翻到目标月份、点日期、需要时点「确定」（Element、Ant Design、Shineout 等都按这个走），都不行才直接写值
- 下拉组件：值和录制时一样就原样重放录到的点击；不一样就点开后点文字等于参数值的选项（能搜索的先输入文字过滤）。级联选择（省/市/区）的值写成「广东省 / 广州市」，按层逐级点
- 原生下拉框：参数填选项的值或文字都行；接口里关联的字段按选项的值发
- 只显示文字、没有输入框或输入框的值一直为空的下拉（Fusion / 千牛、Ant Design、Shineout 的 Select）：点开、点选项后下拉上显示的文字变成了这个选项，同样录成「选择 … 为 {{参数}}」。多选的（选中项显示成一个个标签）每选一项是一步；回放时页面上留着上一次选的标签会先去掉再选
- 区间日期的两个面板各管一头的（Shineout：左边的面板选开始、右边的选结束），开始日期只在左边的面板里选、结束日期只在右边的选

键入后回车、页面把输入框清空的（扫码框、标签输入框、聊天框）照常录成键入和回车，不会当成“选值”。点输入框旁边的日历图标打开的面板、面板里选出的值，同样录成“设置日期”。layui、Chosen、Select2 这类藏起原生下拉框、自己画界面的组件，会记下背后原生下拉框的选项：参数填选项文字，接口发选项的值；界面上选不中时直接设原生下拉框。年份在后的日期（`11/10/2026`）录制时就定下月、日谁在前，回放和接口换算都按它；分不清时请把参数写成 `YYYY-MM-DD`。

点击会记下点完后的展开/收起状态（`aria-expanded` 或“展开”类名，并且里面显示的内容跟着变了）：回放时已经是这个状态（比如左侧菜单分组本来就展开着）就不再点，免得点了反而收起。开关、复选框、按下态按钮同理（`aria-checked`、`aria-pressed`、`aria-selected` 或里面的原生复选框），已经是录制时点完的状态就不再点。页面上有多个一样的元素（多个弹窗里都有“开始日期”）时，按所在弹窗的标题、表单项的标签区分；录制时在弹窗里的目标，回放时会等弹窗出来，不会先点到页面上同名的按钮。表格每行都有的“编辑”“删除”，按录制时那一行前几格的文字找行（等于输入参数的格子跟着参数变），换了数据找不到同一行、又有好几行时报错，不会点到别的记录上。

**iframe 里的页面也能录**，包括跨域的（比如马帮后台的业务页面都嵌在 `aamz.mabangerp.com` 的 iframe 里）。iframe 里的步骤在时间线上会标「iframe · 域名」。回放时扩展会按录制时的 iframe 地址找到对应的框架，在里面执行。iframe 里发出的接口用 `call_api` 直接调用时，也会在那个 iframe 所在的源里调，自动带上它的登录态。UEditor、KindEditor、TinyMCE、CKEditor 4 这类 `about:blank` iframe 编辑器里的输入由外层页面录（目标带 iframe 选择器链）。页面临时建的、没挂到页面上的文件框，和从桌面拖进上传区的文件，也会录成上传；回放时拦下系统的选文件对话框，把参数里的文件设进去。

## 编辑时间线

- **删除步骤**：「时间线」页点「编辑」，点行选择，Shift+点击可以连选一段。勾着「选步骤时带上它触发的请求」时，选中一个步骤会一起选中它触发的请求（比如登录按钮和 `doLogin` 接口）。删掉开头的步骤后，起始页面会改成剩下第一步所在的页面
- **可选步骤**：不是每次都会出现的步骤（比如登录、关广告弹窗）可以设为「可选」：鼠标移到步骤上点「可选」，或在编辑模式里批量「设为可选」。回放时页面上有这个元素就执行，等 3 秒（`CONFIG.optionalTimeout`）还没有就跳过，继续下一步。一个可选步骤被跳过后，紧跟着的可选步骤（登录后续的输入、提交、跳转）会被视为同一组，只快速检查一下

修改会自动同步到脚本库。

**回放默认用真实的鼠标键盘输入**（通过浏览器调试接口，回放期间浏览器上方会提示“正在调试此浏览器”，结束后消失）：页面收到的是和人手操作一样的事件，CSS 悬停菜单、焦点、回车提交、Tab、双击、右键都自然生效；原生 alert / confirm / prompt 按录制时的选择自动应答（没录到的 confirm 一律取消，结果里的 `dialogs` 会标出来）。每次点击前会先等目标停稳（弹出层的展开动画、滑入的面板、jQuery 的滑动菜单都结束、位置不再变化），被加载遮罩挡着就等加载完，按钮暂时禁用就等它可用，元素刚好被页面重新渲染掉就重新找一次；元素已经完整显示在屏幕上时不滚动页面（有的下拉、日历一滚动就会关闭）。浏览器缩放（比如 80%、125%）不影响点击位置。连不上调试接口时自动改用模拟事件，也可以在设置里关掉。结果里的 `input` 是 `real` 或 `synthetic`，`warnings` 列出回放中的警告。

回放时还会自动处理两种常见情况：「打开页面」被服务器重定向（比如已登录时登录页直接跳到后台首页），按跳转后的页面继续；要点的元素在鼠标悬停才展开的下拉菜单里，先模拟悬停展开菜单，展开不了就直接触发点击。

## 接口参数：识别和修改

「接口参数」页会列出每个接口识别出的参数：

- **路径参数**：比如 `/api/order/123/submit` 会识别成 `/api/order/{id}/submit`
- **Query 参数**
- **请求体字段**：JSON 会展开成 `item.qty`、`items[0].id` 这样的路径；表单和 multipart 按字段展开

**想换搜索内容等，改页面顶部的「输入参数」就行**：它就是录制时在输入框里填的内容，回放时会填进输入框；接口里关联了它的字段（显示为「= 输入参数「…」」）会跟着变。脚本库卡片上也能直接改参数再运行：「⚡ 直接请求」不操作页面，直接在页面里请求接口；「▶ 回放操作」在页面上重放录制的操作。下面的接口字段一般不用改：手动改了关联字段，就会固定成你填的值，不再跟着输入参数变（会有提示，可以「恢复关联」）。

像 `index.php?mod=stock.list` 这种靠查询参数区分功能的接口，`mod`、`action`、`method`、`route` 等路由参数会算进接口本身：`mod` 不同就是不同的接口，接口名形如 `POST /index.php?mod=stock.list`。

每个接口的参数取自能关联上输入参数最多的那次调用（并列取最早的；都关联不上时取输入参数都填完之后的那次）。关联规则：值相等（数字字段也算，`{{最低价|num}}`）；日期按日期对应，录到的是「2026/08/20 00:00:00」、接口里是「2026-08-20」「20260820」、时间戳或 `toISOString()` 的 UTC 时间都能关联，调用时换成接口的格式（`{{起始日期|date:YYYY-MM-DD}}`、`{{起始日期|ts:ms}}`、`{{起始日期|iso:start}}`）；区间放在数组里的逐项关联；一个框里两个日期的（「2026-09-01 - 2026-09-30」）按序号分别关联（`#1` 指第二个日期）；自定义下拉的选项文字换成选项的值（`{{仓库|opt}}`）。参数开始填之前页面就已经发过这个值的字段（页面一打开就发 `pageSize=100`）不关联。键名本身带点号的字段写成 `filter\.name`。

**网关式接口**：很多请求走同一个地址、靠请求体里的字段区分做什么（淘宝 mtop 的 `data.url`、GraphQL 的 `operationName`、JSON-RPC 的 `method`、`action` / `cmd`），按这个字段拆成不同的接口，接口名带 `#url=…` 这样的后缀。字段的值本身是 JSON 字符串的（mtop 的 `data`、里面再套的 `jsonBody`），里面等于输入参数的值一样关联（`{{商品标题|jsonesc:2}}`，调用时按嵌套层数转义）。

**选项的编码**：下拉上显示的是文字（「基础分60分及以上」），接口发的是编码（`basic_score_ge60`）。录到的返回里有这张选项表时（筛选项配置、字典接口，套在 JSON 字符串里的也算），会自动找出来：参数照样填文字，接口里的编码字段关联成 `{{质量分筛选|opt}}`，可选的文字列在参数说明里。表里没有的值换不出编码，这次改用页面回放。

直接请求（`mode: "api"`、`call_api`）时，Authorization、token、签名、CSRF 这类请求头，以及录制时脱敏了的令牌字段，用页面自己最近一次请求带的最新值（页面在内存里记着，不会发到别处；签名类只认同一路径；再找不到就看页面上的 CSRF meta、同名隐藏输入框），都拿不到就不发这个请求。凭据模式（带不带 Cookie）照页面当初发这个请求的方式。二进制、流式、录制时被截断的请求体不直接重发。淘宝、天猫、1688 的 mtop 网关（`/h5/<接口>/<版本>/`）每次请求的 `sign` 要现算：页面上有 `lib.mtop` 就交给它发，签名由它算。JSONP 接口照页面的方式用 `<script>` 发。返回的是文件（导出的表格、压缩包）时不当文字读，结果里的 `file` 给出文件名、类型、大小，文本类的（csv）内容照常给；要把文件存下来请用页面回放。推送、WebSocket 这类长连接不直接请求。返回的业务码（`code`、`errorCode`、`statusCode`、`status`、`success`，以及 `head.code` 这类包一层的）和录制时成功的那次不一样，算失败并带上页面给的提示；返回的不是 JSON、顶层字段和录制时完全对不上、或者被重定向到别的路径（多半是登录页），算“结果未知”。

**会过期的东西不用 AI 自己拼**：

- **发放接口**：录制时在后台（脱敏之前、只在内存里）记下每个返回里的值；之后请求里像令牌、票据的值在前面的返回里出现过，就记成“这个字段由那个接口发放”（返回里的某个字段，或返回的地址里的某个参数，Bearer 令牌也算）。直接请求时先调发放接口拿新值再发，结果里 `chained` 列出来。发放接口只认查询类（GET）或路径就是发令牌、票据、签名、地址的，登录、提交、支付这类不会被顺带调用；同一接口自己的翻页游标、列表里某一行的值不算。
- **页面现算的反爬串**：拼多多 `anti-content` / `crawlerInfo`、抖音 `a_bogus`、京东 `h5st`、小红书 `x-s` 这类按名字识别，入库时就打码；名字看不出来、但同一接口每次调用都不一样的长乱串（64 位以上）也算。旧值发出去会被风控拒，扩展也不拿页面上采到的值去伪造请求：`call_api` 改为只重做发出这个接口的那一步（点「查询」「翻页」；页面一打开就发的就重新打开那一页），页面自己组请求、现算反爬串，发出前按调用参数改写业务字段，结果里 `via: "page"`。页面一打开就发、又要改参数的，或者只重做一步拿不到的，结果里 `next` 给出整段页面回放的调用方式。`run_recording` 自动模式遇到这类接口直接回放页面操作。
- **地址里会过期的参数**：名字像令牌、签名、票据的，值像时间戳、随机串的时间戳类参数（`t`、`_`、`nonce`……），以及录制包里已经打了码的。打开页面时依次试：调用时传了 `start_url`（同一页面的新地址）就用它；浏览器里开着同一页面（源、路径、hash 路由和其余参数相同）就用它现在的地址；录制时记下了来源页（同一站点上从哪个页面点进来的），就先打开来源页，找上面指向这个页面的链接，用链接现在的地址；都没有才去掉这些参数再打开，让站点重新发。回放中点链接跳过去的页面，判断“到没到”时不比这些参数，不会再跳回过期的旧地址。iframe 里的接口，没有开着的页面时打开嵌着它的主页面，等主页面把 iframe 建出来再在里面调。
- 开始录制时起始地址就带这类参数，弹窗会提示它是从哪个页面打开的，可以一键回到来源页重新录，把“点进来”的那一步也录进去；以后回放每次都由站点发新参数。

`run_recording` 默认的自动模式：
- 改了的参数没关联到任何接口字段（改了直接请求也不会生效）、录制里有提取页面内容的步骤、有接口的请求体不能重发：回放页面操作
- 改了的参数第一次用：先回放页面操作，同时“校准”——比较页面自己发出的值和直接请求按模板算出来的值，一致的参数以后就直接请求，不一致的一直回放页面操作（结果里 `route` 说明为什么走了页面回放，`calibration` 是校准结果）
- 其余直接请求；被服务端明确拒绝或者根本没发出去、且没有接口已经成功时，改成回放页面操作
- 参数名写错（录制里没有这个参数）直接报错，并列出可用的参数

参数可以直接在弹窗里改，也可以改导出脚本顶部的 `API_PARAMS`。回放时，页面发出的对应请求会被自动改写成新值。只改写和录制值不同的字段，删掉某个键就是从请求里移除这个参数。如果某个参数值等于你在输入框里输入的内容，它会自动关联成 `{{参数名}}`，改了输入，接口参数也跟着变。

## AI 解读接口（把每个接口拆成工具）

AI 会给每个接口起函数名（如 `searchProducts`），写标题、用途、参数说明和返回说明，还会标出埋点之类的无关接口，并给整个脚本起名。有三种用法，任选一种：

- **扩展内直接调用**：在「设置」里配置 AI。支持 OpenAI 兼容接口（OpenAI、DeepSeek、通义千问、Kimi、OpenRouter、本地 Ollama 等）和 Anthropic Claude，Base URL 可以填中转地址（填到 `/v1` 即可，填完整的 `/chat/completions` 也行）。然后在「接口参数」页点「✨ AI 解读接口」。分析在后台进行，可以关掉弹窗；失败原因会一直显示在按钮下方，点 × 才关闭
- **任意 AI 手动解读**：点「复制提示词」发给任意 AI，再把返回的 JSON 用「粘贴 AI 结果」导回来
- **让 Claude Code 等 Agent 解读**：通过桥接服务调用 `get_recording` 分析，再用 `save_api_docs` 写回（见下文）

### 脚本怎么执行

- **控制台**：打开起始页面（保持登录），按 F12 打开 Console，粘贴后回车

- **CDP**：`Runtime.evaluate({ expression: scriptText, awaitPromise: true })`

  ok: true, completed: 10, total: 10,

## 让 Claude Code、Accio 等 AI 工具直接执行（本地桥接服务）

```
AI 工具 ──MCP / HTTP──▶ bridge/server.js ◀──WebSocket── 浏览器扩展 ──▶ 在你的 Chrome 中执行（带登录态）
```

启动桥接服务（需要 Node 18+，无需 `npm install`）：

```bash
npx -y page-recorder-mcp@latest     # 或者从源码：node bridge/server.js
```

扩展会在 30 秒内自动连上，弹窗右上角显示「桥接 ●」。

可选参数（也可以用环境变量）：`--port`（`PR_BRIDGE_PORT`，默认 17321）、`--host`（`PR_BRIDGE_HOST`，默认 127.0.0.1）、`--token`（`PR_BRIDGE_TOKEN`，设置后 HTTP 调用要带 `Authorization: Bearer <口令>`）、`--max-tools`（`PR_MAX_TOOLS`，默认 30，见下面「接口多的时候」）、`--no-auto-update`（`PR_AUTO_UPDATE=0`，不自动更新扩展和技能）。改了端口的话，扩展「设置」里的桥接地址也要改成 `ws://127.0.0.1:<端口>/ext`。

### 接入 Claude Code（MCP）

```bash
# stdio 方式（推荐，不用先手动启动桥接服务）
claude mcp add page-recorder -- npx -y page-recorder-mcp@latest --stdio

# 或者 HTTP 方式（需要先运行 npx -y page-recorder-mcp@latest）
claude mcp add --transport http page-recorder http://127.0.0.1:17321/mcp
```

stdio 方式第一次启动时会在后台起一个桥接服务，之后各个 AI 工具、各次会话都复用它，扩展一直连着，不用每次等它重连。启动过它的程序（WorkBuddy、Cursor、Claude Code 等）都退出后，后台桥接自动关闭；日志在 `~/.page-recorder/`。打开 AI 工具后第一次用时扩展可能还没连上，先只有通用工具，扩展连上后（最多 30 秒）各脚本的工具会自动出现。不想要后台进程的话加 `--no-daemon`。

### 接入 Accio

在 Accio 里添加自定义 MCP：

```json
{
  "name": "page-recorder",
  "type": "local",
  "enabled": true,
  "command": ["npx"],
  "args": ["-y", "page-recorder-mcp@latest", "--stdio"],
  "timeout": 200000

```

新录了脚本以后，在 Accio 里把 page-recorder 断开再连上，工具列表才会更新（通用的 `run_recording`、`call_api` 不受影响）。其他支持 MCP 的工具（WorkBuddy、Claude Desktop、Cursor 等）用同样的命令或 URL 添加。命令里写 `page-recorder-mcp@latest`：发了新版，AI 工具下次启动就用上，扩展和技能也跟着更新；写成全局安装的 `page-recorder-mcp` 或固定版本就一直是旧版。Windows 上直接写 `npx` 启动不了的工具，改成 `"command": "cmd"`、参数前面加 `"/c", "npx"`。不支持 MCP 的工具，可以直接调下面的 REST API。

### 给 AI 的技能（可选）

`skills/page-recorder/SKILL.md` 告诉 AI 怎么用这些工具：先看清接口的参数和返回，再在页面里改参数直接请求；直接请求被拒（要页面现算签名，返回 403）时让页面自己带签名发，并把结论写回接口说明。把 `skills/page-recorder` 文件夹复制到 WorkBuddy 的 `~/.workbuddy/skills/` 或 Claude Code 的 `~/.claude/skills/` 就能用，之后桥接会自动更新它。第一次接管时会把原文件备份到 `~/.page-recorder/skill-backups/`，之后你手动改过的不会被覆盖，符号链接也不会动。

**只给 AI 用你需要的接口**：录制时会抓到很多接口，在「接口参数」页取消勾选不用的「AI 可调用」，MCP 里就只出现勾选的那几个工具。AI 调这些工具时，直接在开着的页面里发请求、拿结果，不操作页面。

### MCP 工具

| 工具 | 作用 |
|---|---|
| `list_recordings` | 列出脚本库：名称、步骤、输入参数、每个接口拆出的工具。整份超过结果上限时改成分页的概要（名称、网址、参数名、接口函数名），`query` 按关键词筛选 |
| `search_apis` | 按关键词在整个脚本库里找接口（接口名、用途、参数名、所属脚本），返回的 `recording_id` 和 `api` 直接交给 `call_api`；`detail: true` 带完整参数定义 |
| `get_recording` | 脚本详情：每个接口的 URL、参数、参数说明、响应结构和示例。内容多时先给概要（步骤、参数、接口目录）和 `result_id`，某个接口用 `read_result` 取 `path: "apis[序号]"` |
| `run_recording` | 运行脚本，可改 `params` 和 `api_params`，返回数据。`mode`：`api` 不操作页面、直接请求关联了输入参数的接口；`ui` 回放页面操作；默认 `auto`（能直接请求就直接请求） |
| `call_api` | 不回放页面操作，直接调用某个接口 |
| `read_result` | 从上一次运行 / 调用 / `get_recording` 的结果里按路径、字段、分页取一部分（不会再调接口） |
| `get_script` | 获取导出的 JS 源码：长的按行分段给（`start_line` / `line_count`），`to_file: true` 写成文件 |
| `save_api_docs` | 把 AI 对接口的分析写回：命名、函数名、用途、参数说明 |
| `merge_recordings` | 把几条脚本按给定顺序接成一条新脚本（原来的不动）：每段可以用 `from_step` / `to_step` 截取，去掉后面几段重复的打开首页、登录。第二段起每段开头直接打开它的起始页面 |
| `export_package` / `import_package` | 导出 / 导入录制包：导出写成文件（`~/.page-recorder/exports/`）、返回路径（HTTP 方式照旧直接返回内容），导入可以传 `file`（HTTP 方式导入要求服务设了 `--token`） |
| `<脚本>__run` | 每个脚本一个，用于整段回放 |
| `<脚本>__<函数名>` | **每个接口一个独立工具**，例如 `product_search__searchProducts` |

**接口多的时候**：AI 每轮对话都要带上全部工具定义，一个接口工具约 680 token，50 个接口就是每轮 3.7 万 token，300 个约 20 万、已经超过常见模型的上下文。所以最后两类工具加起来超过 30 个时就一个都不列，只留上面的固定工具（约 4 千 token）：AI 用 `search_apis` 找到接口，再用 `call_api` 调用，调用本身没有区别。上限用 `--max-tools <数量>`（或 `PR_MAX_TOOLS`）改，`0` = 总是按需查找。

脚本库变化时，服务会发出 `tools/list_changed` 通知，AI 工具会自动刷新工具列表。

**返回给 AI 的结果**：接口返回常常很大（一页商品十几万字符），数据还可能套在 JSON 字符串里（淘宝 mtop 的 `data.result`），原样整段发过去，AI 客户端会截断或报超长。所以运行 / 调用接口的结果会先处理一下：

- 套着的 JSON 字符串展开成对象，路径可以直接往里写（展开过的位置列在 `_decoded_json_strings` 里；要原文，`read_result` 加 `raw: true`）
- 不超过上限（默认 24000 字符，环境变量 `PR_RESULT_CHARS` 或参数 `result_max_chars` 可改）就整段给
- 超过就给压缩过的预览（数组只给开头几项、长文本截短，省略处写明路径）和一个 `result_id`；完整内容留在桥接内存里（最近 30 次、30 分钟内、总共不超过 64MB，`PR_RESULT_CACHE_MB` 可改），用 `read_result` 取：`path` 指到某个对象或数组，`fields` 只留每一项里要的字段，`offset` / `limit` 分页。例如取一页商品的标题和价格：`path: "responses[0].data.data.result.data.table.dataSource"`、`fields: ["itemId", "itemDesc.desc[0].text", "managerPrice.currentPrice"]`
- 已经知道要哪部分时，调用时直接带 `result_path` / `result_fields` / `result_offset` / `result_limit`，一步到位。路径写错也不用重新调接口：返回里带着 `result_id` 和整个结果的预览，改正后用 `read_result` 读
- 接口自己有叫 `result_limit` 这类名字的字段时，这个名字归接口，不当成上面的参数

REST 接口（`/api/recordings/…/run`、`/call`）照旧返回完整的原始结果。

每个输入参数在工具说明里会写清楚：类型（文本 / 日期 / 选择 / 下拉框 / 上传 / 密码）、格式、可选项、是否必填、改了能不能直接请求。

接口工具的参数就是接口的字段。字段的值本身是 JSON 字符串的，里面的字段也各是一个参数（`data.jsonBody.pagination.current`、`data.jsonBody.pagination.pageSize`），只改给了的那个、其余照旧，不用整串重写；没列出来的里层字段按同样的写法给（`data.jsonBody.filter.queryOuterId`）。

**多个浏览器资料都装了扩展**（主 Chrome 加指纹浏览器、几个店铺各一个资料）：桥接同时连着它们，`list_recordings` 汇总各浏览器的脚本库并标出属于哪个浏览器，运行、调用按录制自动发到拥有它的那个浏览器；同名脚本分不清时报错，用工具的 `browser` 参数指定（扩展「设置」里可以给每个浏览器起名字）。桥接只接受 Host 为 127.0.0.1 / localhost 的请求。

**桥接只认 Page Recorder 扩展**：本机装的任何扩展都连得上 `127.0.0.1:17321`，连上就能收到 AI 发来的参数（包括密码）、读写脚本库备份，所以桥接要核对是谁：每个连上来的扩展（第一个也一样），桥接都要找到它的安装目录才放行，认过的记下来，下次不再核对。认的目录有两种：`extension` 子命令生成的目录、默认目录 `~/page-recorder-extension` 这类桥接自己管的目录；或者浏览器资料里登记的已解压扩展目录，但里面的扩展文件要和当前版本逐个一样（照抄名字、改了代码的过不了）。指纹浏览器这类自定义资料目录找不到时，扩展弹窗的桥接状态会显示它的 ID，确认是自己装的就在终端运行 `npx page-recorder-mcp trust <扩展ID>` 放行（或者把资料目录写进环境变量 `PR_BROWSER_DATA_DIRS`）。启动参数里给了 `--extension-id`，或者设了 `--token`，就按那个来，不做这项核对。

可以直接对 Claude Code 说：
> 用 page-recorder 看看脚本库，分析「商品搜索下单」每个接口是做什么的，把说明保存回去，然后搜索 macbook 第 2 页给我看结果。

**分开录的几段流程合成一条**：比如「登录」「搜索商品」「导出订单」各录了一条，可以对 AI 说：
> 用 page-recorder 把「登录」「搜索商品」「导出订单」排好先后合成一条新脚本，后面几段重复的登录步骤去掉。

AI 会先看每条的起始页面和步骤，定好顺序后调用 `merge_recordings`，再核对步骤、写接口说明。几段在同一个输入框里输入过时，合并后前面几次的参数名带「_第N次」。

### REST API

```bash
curl http://127.0.0.1:17321/api/recordings                    # 列表
curl http://127.0.0.1:17321/api/recordings/商品搜索下单           # 详情（id 或名称都可以）
curl http://127.0.0.1:17321/api/recordings/商品搜索下单/script    # JS 源码

# 回放：改输入框参数和接口参数
curl -X POST http://127.0.0.1:17321/api/recordings/商品搜索下单/run \
  -H 'content-type: application/json' \
  -d '{"params":{"搜索商品":"macbook"},"apiParams":{"GET /api/search":{"query":{"page":"2"}}}}'

# 调用单个接口
curl -X POST http://127.0.0.1:17321/api/recordings/商品搜索下单/call \
  -H 'content-type: application/json' -d '{"api":"searchProducts","args":{"q":"ipad","page":2}}'
```

`run` 的可选参数：`mode`（`auto` / `api` / `ui`，见上）、`fresh`（复用的标签页先刷新回起始页面）、`newTab`（用全新标签页、跑完关掉）、`keepTab`（配合 `newTab` 保留标签页）、`active`（在前台执行，方便观察）、`timeout`（毫秒，默认 180000）。

**回放返回的数据**：`responses` 是每一步关联的接口返回；`network` 是回放期间这个标签页里所有框架（包括整页跳转后的新页面、跨域 iframe）发出的全部接口及返回（最多 300 条），按时间排列，`frame` 字段标明来自哪个 iframe。直接请求模式下，结果在 `responses` 里。

**页面复用**：直接请求和 `call_api` 会在已经开着的同源页面里发请求，带着浏览器的 Cookie、登录态和录制时的请求头。第一次没有合适的页面时，会在后台打开一个并留着，之后的请求直接复用，不用每次都打开页面。页面回放（`mode: ui`）也会复用这条录制上次的回放标签页。

### 安全

- 服务只监听 `127.0.0.1`。带 `Origin` 头的跨站请求会被拒绝，网页无法偷偷调用它；只有扩展能通过 WebSocket 连进来
- 需要更严格的控制时，设置 `--token xxx`（或 `PR_BRIDGE_TOKEN=xxx`）：之后 HTTP 调用要带 `Authorization: Bearer xxx`，扩展「设置」里的桥接地址也要写成 `ws://127.0.0.1:17321/ext?token=xxx`
- 用 `--host` 监听本机以外的地址时必须设置 token，否则服务拒绝启动
- 端口可以用 `PR_BRIDGE_PORT` 修改，扩展「设置」里的地址要同步修改
- 脚本在你已登录的浏览器里执行，能做你在页面上能做的一切。请只接入你信任的 AI 工具

## 已知限制

- 新开的标签页（`target=_blank`、`window.open`）里只抓请求，操作不录制；closed Shadow DOM 不录；扩展安装或重新加载前就打开的页面（包括里面的 iframe）要刷新一次才能录
- 导出的控制台脚本不能操作跨域 iframe，遇到 iframe 里的步骤会停下并提示；这类录制请用扩展脚本库的「▶ 运行」或桥接服务的 `run_recording`。控制台脚本也没有真实输入和上传能力
- Worker 里的请求、表单提交、下载只有请求信息、没有返回内容；WebSocket 和推送只记开头的几条消息，不能直接请求；Service Worker 自己发的请求不抓。上传要在参数里给本机文件的完整路径（跨域 iframe 里的上传暂不支持），没给就停下报错
- 下拉的选项写死在页面代码里、录到的返回里都没有选项表时，接口里的编码字段关联不上：改这个参数只能回放页面操作，不能直接请求（接口工具里可以直接给编码字段传值）
- 日历驱动按面板上显示的年月翻页；面板头部读不出年月、或者翻页按钮认不出来时，会退回直接写值并在 `warnings` 里提示
- 控制台脚本遇到跨域整页跳转时，之前已收集的 `responses` 和 `extracted` 不会带到新页面（扩展和桥接回放没有这个问题）
- 签名类请求头会用页面最近一次请求同一接口时的值；页面还没请求过这个接口、或者签名和请求体绑定时，直接调用可能被拒绝（会按业务码判为失败），这种情况 `run_recording` 会自动改成回放页面操作（写接口只有返回 401 / 403 或根本没发出去时才自动回放，其他失败说不准有没有生效，不会自动再发一次）
